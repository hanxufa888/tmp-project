# チェック項目No.
CHK-110

# チェック項目
仕様書内の記載表現にて、用語が統一されているか。同一の意味だが異なる用語で記述されていないか。

# チェック判定仕様
用語統一の確認は、以下の手順1→手順2の順に実施する。

## 手順1. 対象用語の抽出
仕様変更箇所から、確認対象とする用語を以下のルールで抽出する。抽出した用語のみを手順2の照合対象とする。

- 用語は、before_markdown と after_markdown を対比し、**実際に仕様変更された箇所（追加・変更・削除されたセル/トークン）**から抽出する。
- 同じ差分レコード（行・章節）内に含まれていても、before と after で一致する（＝未変更の）セル・記載からは抽出しないこと。
- 抽出した用語は漏れなく列挙し、各用語について手順2を実施する。

## 手順2. 用語統一の照合
手順1で抽出した各用語について、同一仕様書内で、その用語と仕様書内において同一の対象（機能・状態・表示・信号等）を指していると解釈される用語がないか確認する。
（例：BEV/ EVのような別表現）
上記の文言があれば「問題あり」, そうでなければ「問題なし」と判定する。

なお、本確認において漢字／かな違いなどの単純な表記揺れは対象外とする。
また、「A/B」のようにスラッシュ「/」で区切られた表記は「A または B」を表す複合表記（選択表記）とみなす。ある用語と、その用語を構成要素（オペランド）の一方に一致して含むスラッシュ複合表記（例：「大型」と「大型/Slope」）とが、同一仕様書内で同一の対象を指している場合は、両者を同一表現とみなし、用語不統一（同一意味・別表現）としては扱わない（＝「問題あり」としない）。
ただし、同一仕様書内の他章節・項目を指す参照表現については、紐づけを一意に保つため、参照元で使用している用語と参照先で使用している用語が完全一致していない場合（英字↔カタカナ等の書記体系差を含む）は用語不統一として「問題あり」とする。
　この参照表現の照合は、参照元・参照先の**いずれか一方**が手順1の抽出箇所（＝実際に変更されたセル）に該当すれば実施する。すなわち以下の双方向をともに対象とする。
　- (a) 変更箇所が参照元（他章節・項目を指す側）の場合：その参照先の用語と照合する。
　- (b) 変更箇所が参照先（他所から参照される対象。例：新規追加・変更した章節／項目）の場合：同一仕様書内で当該対象を指す参照表現（参照元）を、**その参照元セルが本レコードで変更されていなくても**網羅的に走査する。参照表現は「シート名・章節名（章節番号を含む）・項目名」等の複数の構成要素からなる参照ロケータであり、その**各構成要素をそれぞれ個別に**、変更後の正式名称と完全一致するか照合する。**いずれか一つの構成要素でも完全一致しない場合（シート名の相違を含む）は「問題あり」とする。** 章節名など一部の構成要素のみが一致していることをもって「問題なし」と判断してはならない。特にシート名の略記・省略（ハイフン「-」や接尾語「定義」等の欠落）を見落とさないこと。
　いずれの場合も、参照元と参照先の用語が完全一致していなければ（英字↔カタカナ、略記↔正式名等の書記体系差を含む）「問題あり」とする。
　なお、(b) において参照元セルが本レコードの変更対象でないことを理由に照合を打ち切り「対象外」としてはならない。
