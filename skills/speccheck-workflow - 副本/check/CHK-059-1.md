# チェック項目No. 
CHK-059-1

# チェック項目
・参照先仕様書と整合は取れているか？
・参照先仕様書と仕様書名/章番号/項目名/記載内容は一致するか？
【MET-M_MCUCONST-CSTD-を参照している場合】
・MCUIDを記載しているか？（定数名のみの記載不可。一意に定まるMCUIDの記載が必要）

# チェック判定仕様
## 【手順実施の原則】
- 手順1～4は独立した観点のチェックである。いずれかの手順で「問題あり」となっても、
  残りの手順を省略せず、全手順を最後まで実施すること。
- 各手順の判断結果（問題なし/問題あり/対象外/要確認）を個別に記録し、最終判断は全手順の
  結果を統合して行うこと。
- 「対象外」と判断する場合は、対象外とする根拠を明記すること。
- 【出力義務】判定理由には、手順1～4のそれぞれについて実施結果（問題なし/問題あり/対象外/要確認）
  と根拠を必ず明記すること。ある手順で「問題あり」が確定した場合でも、それ以外の手順
  （先行・後続いずれも）の実施結果の出力を省略してはならない。
- 【手順3の全件出力】手順3は、列挙した参照先仕様書の「全件」について確認結果を
  個別に出力すること。他の手順で「問題あり」が確定していること、または一部参照先が確認不能
  であることを理由に、手順3の全件出力を省略・短縮してはならない。
- 【連鎖参照を最後まで辿る（必須）】参照先（別仕様書／同一仕様書内の別章節のいずれも含む）の
  該当箇所に、さらに別の参照（参照先仕様書・章番号・項目名）が記載されている場合は、
  その連鎖先も必ず辿ること。参照が尽きる（新たな参照記載が現れなくなる）まで連鎖を最後まで
  辿り、各段の記載内容の整合を確認する。「参照先の存在（章番号・項目名が実在すること）の
  確認のみ」で打ち切ることを禁止する。連鎖の最終的な記載内容が、起点である元の章節
  （チェック対象の章節）の要求と矛盾しないかまで遡って判断すること（手順3-1-a を参照）。
- 【参照先とみなす記載の限定（本チェックのスコープ）】整合確認の対象は、対象箇所に
  **明示的な参照記載**（参照先仕様書名、または参照指示語（「〜参照」「〜による」「〜に従う」「〜にあわせる」「別紙〜」等）を伴う章番号・項目名の指定）
  があるものに限る。信号名・定数名・項目名が参照指示語を伴わず本文で使用されているだけの場合は参照とみなさず、定義の有無・定義先との整合は本チェックのスコープ外とし、定義不在を理由に「問題あり」としない。
  明示的な参照記載が一切ない場合は手順2〜4を行わず「問題なし（対象外：参照記載なし）」とする。

## 新フォーマットの場合

1. 項目「特別処理」（変更点箇所のセル）に記載された参照先（【手順実施の原則】「参照先とみなす記載の限定」に該当する明示的な参照記載）を探索する。

   - 変更点箇所のセル内に、参照先仕様書名・参照指示語を伴う章番号/項目名のいずれの記載も無い場合は、整合確認の対象が存在しないため、手順2～4は不要とし、判定は「問題なし（対象外：参照記載なし）」とする。
   - 参照先仕様書名の記載がなく、参照指示語を伴う章番号や項目名が記載されている場合は、チェック対象の仕様書内を対象とし、手順2に移行する。
   - 参照先仕様書名の記載がある場合は、その参照先仕様書を確認対象として手順2に移行する。

2. 項目「特別処理」に記載されている参照先仕様書の章番号や項目名が実際の参照先仕様書の章番号や項目名や説明と一致しているかを確認する。
章番号/項目名が一致している場合は「問題なし」、一致していない場合は「問題あり」と判断する。
章番号/項目名の記載がない場合は章番号/項目名の確認は本確認を除外し、手順3に移行する。

3. 参照関係について、以下の手順で確認すること。
   3-1. 対象箇所（特別処理セル等）に含まれる参照先（参照先仕様書・章番号・項目名）を
        **すべて**列挙する。
   3-1-a. 連鎖参照（【手順実施の原則】参照）がある場合は、連鎖先も列挙対象に追加する。
        連鎖の各段について、どの参照元（章節・No.）からどの連鎖先へ辿ったかを判定理由に
        明記する（例：5-3-2（基本画面No.3）→ 11-3 No.5 →「11-2 No.5参照」→
        11-2 No.5(6) →「MET-C_CRAWL-CSTD-A0-」5-1.No.2.3）。連鎖先を確認できない場合は
        3-3-a に従い「要確認」とする（上流の参照先を「確認済み＝問題なし」で打ち切らないこと）。
   3-2. 列挙・展開した参照先（連鎖先を含む）の**各々**について、以下を確認する。
        - 参照元から参照先へ委ねている内容に対し、参照先において該当内容の説明が
          記載されているか
        - 参照元に記載された値・条件・定義が、参照先の記載内容と矛盾していないか
          （例：定数値と定数選択肢の対応、信号名の存在有無、ビット定義の一致等）
        - 連鎖参照で辿り着いた最終的な記載内容が、起点である元の章節（チェック対象の章節）
          の要求と矛盾していないか（元章節まで遡って整合を判断する）
   3-3. いずれか1つの参照先（連鎖先を含む）でも、説明の不足・記載内容の矛盾・該当記述の
        不在が確認された場合は「問題あり」と判断する。
   3-3-a. 参照先仕様書が探索範囲内に存在せず内容を確認できない場合は、当該参照先を
        「要確認（参照先不在・確認不能）」として記録し、確認不能である旨と探索範囲を
        判定理由に明記する。存在しないことを理由に当該参照先の出力を省略しない。
        （「問題あり」/「問題なし」の確定材料とはしないが、要確認として最終判定の統合に必ず反映する）
   3-4. 判定出力時に、列挙・展開した全参照先（連鎖先を含む）について確認結果を個別に
        記載すること。確認を省略した参照先がある場合は、その理由を明記すること。

4. 項目「特別処理」に記載されている参照先仕様書が`MET-M_MCUCONST-CSTD-`である場合のみ、手順4を実施する。
   項目「特別処理」にMCUIDの記載がなく定数名のみ記載されている場合は「問題あり」、MCUIDの記載がある場合は「問題なし」と判断する。
   なお、MCUIDのみ記載があり定数名の記載が無い場合は「問題なし」判断とする。

## 判定理由の必須出力フォーマット（手順別・両フォーマット共通）
判定理由は以下の構造で必ず出力すること（各行が空でも省略不可）。
- 手順1（参照先列挙）：列挙した参照先仕様書を全件記載
- 手順2（章番号/項目名の一致）：問題なし / 問題あり / 対象外（根拠）
- 手順3（参照関係の確認）：参照先ごとに1行
    「<参照先仕様書名（連鎖の場合は辿った経路）>：問題なし / 問題あり / 要確認 — 確認した内容・根拠（章節・記載）」
    を、連鎖先を含む全件について列挙
- 手順4（MET-M_MCUCONST-CSTD- 参照時のMCUID確認）：対象有無を記載し、
    対象の場合は 「問題なし」 / 「問題あり」（MCUID記載有無の根拠）
- 最終判定：各手順の結果を統合した結論（「問題あり」が1つでもあれば「問題あり」）

## 自己チェック（出力前の内部確認・判定理由には出力しない）
本セクションは出力前の内部確認用であり、確認結果を判定理由（出力）に記載しないこと。
- [ ] 手順1～4それぞれの結果（問題なし/問題あり/対象外/要確認）を判定理由に明記したか？
- [ ] 手順4で「問題あり」確定でも、手順3の全参照先の確認結果を個別出力したか？
- [ ] 探索範囲内に存在しない参照先を「要確認」として明記したか（省略していないか）？
- [ ] 列挙した参照先の件数と、手順3で出力した確認結果の件数が一致しているか？
- [ ] 参照先の該当箇所にさらに別の参照が記載されている場合、連鎖先を最後まで辿り、元章節との整合まで確認したか？（存在確認のみで打ち切っていないか）
